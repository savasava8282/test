# Roadmap проекта «Погода и магнитные бури»

## Принцип работы

Каждый новый этап начинается только после проверки предыдущего. Один запуск Codex — одна ограниченная техническая задача.

## Этап 0. Обязательные правила

1. Прочитать обязательные правила student-kit.
2. Зафиксировать правила в рабочем контексте текущего диалога.
3. Прочитать `rules.md` проекта.
4. Не начинать технические действия, пока не восстановлен текущий stop-point.

## Этап 1. Стартовая документация

1. Согласовать идею.
2. Провести стартовую разведку рынка и источников данных.
3. Согласовать техническое задание.
4. Создать резервные Markdown-документы:
   - `technical_spec.md`;
   - `roadmap.md`;
   - `rules.md`;
   - `current_status.md`;
   - `module_map.md`;
   - `start_prompt_for_next_chat.md`.
5. Не создавать `next_steps.md`.

## Этап 2. GitHub-репозиторий

1. Уточнить, есть ли у пользователя аккаунт GitHub.
2. Создать или подготовить пустой GitHub-репозиторий.
3. Проверить ссылку и текущее содержимое репозитория.
4. Не начинать разработку приложения.

## Этап 3. Deploy key для Codex

1. Дать Codex отдельную задачу на проверку репозитория.
2. Создать или найти SSH deploy key внутри среды Codex.
3. Private key оставить только внутри среды Codex.
4. Показать пользователю только public key.
5. Добавить public key в GitHub через `Settings → Deploy keys → Add deploy key`.
6. Включить `Allow write access`.
7. Если SSH-порт 22 недоступен, использовать `ssh.github.com` и порт 443.
8. Не использовать GitHub-интеграцию Codex и не создавать GitHub token в базовом процессе.

## Этап 4. Рабочая документация в GitHub

1. Проверить SSH-доступ Codex через deploy key.
2. Настроить SSH remote.
3. Создать в корне репозитория ровно шесть согласованных Markdown-файлов.
4. Не создавать `next_steps.md`.
5. Не создавать код приложения.
6. Проверить список изменений.
7. Сделать commit.
8. Сделать push.
9. Получить commit hash или ссылку на commit.
10. Проверить результат через GitHub.

## Этап 5. Первая техническая основа

1. Получить proof текущего состояния репозитория.
2. Выбрать минимальную структуру Python-проекта.
3. Добавить конфигурацию без секретов.
4. Добавить локальную SQLite-базу и схему настроек — выполнено в commit `3007f15c2b9645de015691c9ceafb4e7a3ad1eeb`.
5. Добавить безопасное чтение переменных окружения.
6. Добавить минимальный запуск приложения.
7. Проверить запуск.
8. Сделать отдельный commit и push.

3. Настроить токен только на сервере.
4. Реализовать `/start`, `/help`, `/settings`, `/today` как отдельные небольшие задачи.
5. Проверить ответы в реальном Telegram.
6. Зафиксировать результат в Git.
