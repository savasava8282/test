## Историческая запись перед реальным тестом `--wait-for-daily-days`

Для старой схемы без `daily_send_time` сохраняется прежняя безопасная миграция времени; для текущей схемы с пользовательским `daily_send_time` добавляется только `daily_send_days` через `ALTER TABLE ... ADD COLUMN`, без удаления таблицы или строк. Повторная инициализация идемпотентна.
- Автоматические тесты подтвердили миграцию текущей схемы с `daily_send_time = 08:30`: город, координаты, timezone и пользовательское время сохраняются, существующая строка получает `daily_send_days = 1,2,3,4,5,6,7`. Реальная пользовательская база не открывалась и не изменялась.
- `save_confirmed_city()` при upsert меняет только город, координаты и timezone; существующие `daily_send_time` и `daily_send_days` не сбрасываются. `save_daily_send_days()` нормализует и обновляет только существующую строку, не создавая пользователя без города.
- Добавлены `normalize_daily_send_days()` и отдельный режим `--wait-for-daily-days`.
